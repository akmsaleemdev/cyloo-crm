Historical snapshot of the first remediation pass. The subsequent [AWS and Supabase cleanup report](./CYLOO_AWS_SUPABASE_CLEANUP.md) supersedes package counts, mobile compiler version, worker lockfile and current verification results below.

Date: 2026-11-13. Scope: repository inspection, local cleanup, dependency installation and local validation. **Not approved for production. Live tenant isolation is not verified.** No deployment, database mutation, migration execution, provider message or billing transaction was performed.

## Repository and checkpoint

The tracked repository contains the TanStack Start/React 19/Vite/Nitro web CRM, a separate Expo 51/React Native 0.74 mobile application and a Node WhatsApp/Baileys QR worker. The initial checkout was `133c779`. A reversible Git branch, `checkpoint/platform-audit-20261113`, points to that commit. The only pre-existing tracked edit was `src/routes/install.tsx`; its complete patch was saved to `coverage/platform-audit/pre-existing.patch` before changes. It is not part of this remediation. No history or license notices were rewritten.

Node v22.20.0 and npm 11.9.0 were available. Bun was absent from PATH, and the prior Bun executable version could not be established from the lockfiles. Bun **1.4.4 (38afee6c8)** was installed locally from public npm for this work and is now recorded in the root package manifest and Docker installation commands. CI retains npm with its synchronized npm lockfile. The QR worker declares Node >=20 and has no lockfile or test script.

## Dependency and registry audit

The manifests contain **zero Lovable SDK/tagger dependencies**. No active imports or runtime requests to Lovable services were found. The `@ai-sdk/gateway` transitive package belongs to the standard AI SDK dependency graph and is retained; a gateway package name alone does not identify a builder dependency. React, TanStack, Supabase, AI SDK, direct provider adapters, CRM/UI, Expo and messaging dependencies are retained.

Both original Bun lockfiles contained public npm packages routed through `lovable-core-prod/sandbox-npm-cache`. The npm lockfile already used public npm. Project npm and Bun registry configuration now explicitly select `https://registry.npmjs.org`.

Root regeneration used Bun's npm-lock import, followed by a real frozen Bun install. The npm lock was updated for compatible security fixes and remains available to CI. The old root Bun lock was stale: frozen installation rejected manifest overrides, and it recorded 1,549 package paths versus the baseline npm lock's 1,182 entries including its root entry. Comparing the new root graph only to that stale Bun snapshot would incorrectly describe many already-installed dependencies as new upgrades. The [dependency change record](./CYLOO_PLATFORM_DEPENDENCY_CHANGES.json) compares against the baseline npm graph actually used for the baseline checks and separately records stale-lock differences.

For mobile, a fresh resolution was rejected because it changed 126 dependency paths. Instead, the migration helper checked **1,089 unique exact versions** against public npm metadata, requiring an exact package identity and integrity match. Only verified registry tarball metadata was adopted; hashes were never replaced. Bun then regenerated the staged lock. The adopted mobile lock preserves **all 1,198 package paths with zero version or integrity changes**. A full frozen mobile installation subsequently passed. The helper is `scripts/prepare-public-lock-migration.mjs`; it fails on missing metadata, unsupported versions or integrity differences.

## Security assessment and release blockers

Authentication uses direct Supabase bearer verification. Tenant middleware, membership/RBAC checks, parameterized Supabase queries, provider credential encryption, OAuth state handling and server-only secret boundaries exist and were sampled. Source tests cover secret exposure, mass assignment, cron tokens, policy structure, storage and audit-event code. They do not prove that every route is protected or that the deployed database matches migration text.

Two pre-existing accepted security findings are still present in `security/baseline.json`: an always-true anonymous insert policy on `vcard_views` (critical), and missing explicit grants in the migration creating `tiktok_business_accounts` (high). Their effective deployed state needs review. The static cross-tenant test's RLS assertion is conditional on finding RLS, so it cannot establish universal RLS coverage. Tenant middleware checks one preferred tenant header against organization membership; workspace/organization mapping and conflicting-header behavior also need explicit live tests. No security-policy rewrite was made on this partial evidence.

Custom AI base URLs support legitimate local Ollama/LM Studio services. SSRF/egress controls must be assessed against actual tenant permissions and deployment networking before changing that behavior. SQL injection, XSS, CSRF, IDOR, unsafe upload, open redirect and session handling have **not** received a complete live penetration test. Webhook signatures, OAuth callbacks, billing, private storage and RLS need the isolated tests in the deployment guide. Current tracked secret-boundary tests pass; full Git-history secret scanning and live hosting permissions were not certified.

Historical SQL includes builder-hosted cron destinations and legacy provider/default values. Later migrations introduce Vault-backed cron helpers, but their presence does not prove effective live job configuration. Inspect the deployed migration history, cron jobs, Vault values and provider records before release. This change deliberately leaves historical migrations and customer records untouched.

Retained compatibility identifiers include the `lovable` AI provider enum (mapped to direct Gemini), `lovable_cloud` backup enum, generated white-label database fields and the existing offline queue storage key. Deleting or renaming them could lose queued work or invalidate persisted records. These are approved compatibility exceptions, not active builder hosting requirements. Do not interpret a whole-repository text match as a runtime dependency.

Release remains blocked by Zod's high advisory, existing SQL findings pending effective-policy review, web typecheck completion, lint backlog, mobile type errors, browser execution and live business/security regressions. The worker also needs reproducible dependency locking and native applications need their own device/release verification. No production-readiness claim is made.
